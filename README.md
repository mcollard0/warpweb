# Warp mobile client
Version **0.0.1**, defined in `app/__init__.py` and used by the FastAPI application metadata.
A password-gated, mobile-friendly web client for browsing Warp agent runs, reading conversation cards, and creating or continuing local Oz CLI sessions.

FastAPI fetches history and metadata through Warp REST using a server-only API key. Local tasks run through the Warp CLI with private prompt files; desktop runs remain read-only.

Both task inputs support **Ctrl+Enter** to send; Enter adds a newline. Submitted tasks appear immediately as User cards. Tool commands/inputs stay visible while output is expandable, and prose renders sanitized Markdown. Send buttons use rocket icons.

The **Options** gear saves settings in this browser: recent directories (default 20), history window (8 KiB), conversation-card preview (12 lines), and cost refresh every N accepted prompts (default 1). Directories are remembered only after accepted submissions; options can be reset and recent directories cleared. Cost is per run, not an account balance or conversation total.

Each submitted turn launches a separate `warp agent run` process; following turns use `--conversation` to continue the same conversation. Finished local CLI conversations can be continued even when created outside Warpweb. Active external CLI runs must finish first. When Warp supplies a shared-session link, the client offers it for desktop/active-session access; steering there requires Warp edit access. No public active-run messaging endpoint is used.
The red **Stop** control beside X cancels a running local agent **launched by Warpweb**; X still only minimizes. Stop targets the owned process group, shows Stopping, then Cancelled locally, and does not undo existing file changes. The next-command input stays available for app-owned sessions while a turn runs; **Send enables after the process exits and cleanup is confirmed**, continuing the same verified conversation even when upstream status briefly lags. Stop does not send text to the AI. If the first turn stops before a conversation identity can be recovered, an explicit action starts a new session with your next command instead.
App-owned sessions recover after page refresh, including before a verified run ID is available. Swipe horizontally in the conversation history, or use Previous/Next, to switch sessions. Drafts and working-directory/model selections remain session-specific in page memory; opening or switching sessions does not stop them or make them read-only. Up to **two local turns can run concurrently**, with only one turn at a time per conversation. External desktop/local/cloud runs cannot be stopped through this control. A purple W favicon is served with the page.
Choose a model when creating a session or for each next turn. On the session page, the **down-arrow directly above the rocket** opens working-directory and next-turn model settings above the composer; they stay hidden until needed. Closing the panel preserves selections. Choices come from the installed CLI model catalog; Default remains usable if discovery is unavailable. Changing the selector does not alter an already-running turn.
If a requested directory is missing or misspelled, including a workspace-root name typo, Warpweb launches from an existing allowed workspace and privately sends the original directory text to the agent as search intent. The agent must find the intended directory within allowed roots and change into it before work, or ask for clarification if unsure; it must not create a directory or silently work in the fallback. The GUI distinguishes the requested directory from the launch directory. Existing outside-root directories, files, explicit traversal escapes, and symlink escapes remain rejected.


Start with **[INSTALL.md](INSTALL.md)** for the Personal-token setup, interactive `INSTALL.sh`, private credential storage, user systemd service, and optional HTTPS hosting. Run `./INSTALL.sh --check` for a non-destructive prerequisite check.

See [architecture.md](architecture.md) for API details and limitations. For development, install server dependencies with `.venv/bin/python -m pip install -r requirements.txt` and test dependencies with `.venv/bin/python -m pip install -r tests/requirements.txt`. Run `.venv/bin/python -m pytest -q tests`; mocked browser tests use Playwright and an installed `chromium` executable without contacting Warp or running agents.

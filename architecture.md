# Warp mobile agent client
## Current feature status
The password-gated mobile chooser lists local Warp **agent runs**, with optional cloud/all filters, descriptions, age, status, and reported credit/approximate USD cost. A selected run shows a scrollable conversation with User, Agent, and Tool cards; tool calls show command/input without expansion and results remain under an Output disclosure. Calls/results are paired only when supplied action IDs match. X returns to the chooser without stopping a run. History loads the latest ~8 KiB by default (4–16 KiB configurable), prepends older turn windows on upward scroll, and polls active runs every six seconds. Metadata polling updates status and automatically enables continuation once an external CLI run finishes. Authenticated direct links use `?run=<runId>`.
New session starts a local CLI process on this machine. The composer continues finished `CLI / LOCAL` conversations by launching another local CLI run with the same conversation ID, including runs created outside warpweb. Both textareas support Ctrl+Enter submission; Enter remains a newline. User cards appear before POST completion, retain rejected input for edit/retry, and remain visible through progress/run transitions. Submission and render callbacks are guarded against unrelated-view updates. Pending cards, their original task text, and the bounded render cache live only in page memory; canonical Warp history may contain the private-task-file instruction rather than the literal submitted task after a page reload.
App-owned sessions keep an editable next-command composer during execution; Send is disabled until that conversation's owned job has exited and cleanup is confirmed. The server can continue verified completed/cancelled/failed jobs despite stale upstream active status, using an authenticated owned-job endpoint without needing another REST request. Follow-up jobs retain their already-verified conversation identity separately from verification of their new run ID, so stopping a turn before run-start metadata does not discard the conversation. First turns without recoverable identity instead offer an explicit new-session action; no continuation identity is guessed. Stop remains process cancellation, not AI text delivery or live steering.
Frontend job snapshots/watchers and submission guards are keyed by job/session identity instead of one global running job. Page refresh uses `?job=<opaque-id>` for first turns awaiting verification and `?run=<verified-id>` once history can attach, with authenticated discovery/metadata restoring owned controls. History/metadata refresh is selected-view/epoch guarded; background completion cannot switch another viewed session, clear its draft, or enable its Send button. Logout clears cached jobs, watchers, drafts, and submission state; authentication epochs reject delayed mutation replies. Draft prompts/cwd/model values live only in page memory, not localStorage.
Next-turn cwd/model controls default to a collapsed panel above the composer, opened by an accessible arrow directly above the rocket. `aria-controls`/`aria-expanded` describe the disclosure; keyboard activation works, hiding preserves values, and restoring another session closes the panel without discarding its draft selections. Invalid hidden directory input opens the panel before browser validation focuses it.
The session navigation list deduplicates conversations and includes unverified owned jobs; horizontal history swipes and accessible Previous/Next buttons only change selection. Gestures with vertical intent, multiple touches, editable/interactive targets, disclosures, or horizontally overflowing content do not navigate. The existing two-job limit applies server-wide, with a same-conversation lock; navigation never terminates jobs or turns owned sessions read-only.
Jobs are polled every 2.5 seconds. The CLI-reported run ID is exposed during execution only after REST verifies `CLI / LOCAL`, allowing canonical tool history to load before process completion. CLI text progress remains a bounded fallback; unavailable command/output is not fabricated. There is no WebSocket transport. Desktop and active external runs remain read-only inside warpweb; a validated upstream Warp shared-session link is offered when present, with edit access required for steering there.
The page links a self-contained purple W favicon at `GET /assets/favicon.svg`, served publicly by the existing static mount, including before login. It uses vector shapes rather than external fonts or scripts and remains subject to the existing no-store/security headers. Static-file changes are available without a service restart.
## Local job cancellation
The session header has a red Stop agent control beside the minimize-only X. It appears only for a currently viewed, app-owned running job and disables while Stopping. Authenticated active-job discovery restores controls after reload, including unverified jobs; associated `local_job` metadata restores verified-run controls. If Warp history/metadata is unavailable, exact verified job/run matching through local discovery still permits stopping. Delayed cancellation responses cannot switch job identity or alter an unrelated view. Local cancellation preserves cards and reports Cancelled locally separately from Warp's possibly delayed run status. Eligible final usage refresh is asynchronous and selection-guarded.
After confirmed cleanup, up to three short bounded metadata attempts recover missing run/conversation verification before the terminal state is published. A trusted continuation conversation does not require a new run ID to remain resumable. `can_resume` requires trusted conversation identity, completed/cancelled/failed state, no retained process handle, and no active job in that conversation. Active job association by exact conversation also locks composers on older runs of that same conversation.
Each job retains its private `Popen` handle and optional termination task/event, never serialized into browser payloads. Running/stopping states occupy both concurrency slots and same-conversation locks; terminal states are completed, cancelled, or failed. Cancellation is idempotent, rejects unowned/already-exited processes, sends TERM to the exact owned process group, allows five seconds, then sends KILL to survivors and confirms group-wide exit within two seconds before reaping the leader. On Linux, `/proc` group/state checks distinguish live children from exited zombies; an exited leader alone is not sufficient confirmation. Cancellation interrupts in-flight Warp verification; timeout/error/shutdown monitoring uses the same bounded cleanup. Process termination is confirmed before releasing ownership or cleaning the private task file. If termination cannot be confirmed, the job remains Stopping with an error and keeps its slot. Intentionally detached descendants outside the process group are not covered; cancellation cannot undo filesystem changes.
Only local CLI processes launched by this service are cancellable. No PID is accepted from a browser, no process is discovered/killed by name, and no external local/desktop/cloud run is cancelled through Warp REST. Restarting the service clears the in-memory job registry and browser logins.
## Browser options
`app/static/preferences.js` stores validated options, recent directories, and up to 100 conversation prompt counters in `localStorage` under `warpweb.preferences.v1`. No prompts, passwords, or API keys are saved there. Settings are per browser/device, with in-memory fallback if storage is disabled:
- MRU directory limit: default 20, range 1–100. Both cwd inputs share suggestions and remain editable. Record the canonical cwd from accepted submissions, deduplicate, trim immediately on limit changes, and provide clear-history control. Clearing suggestions does not change the selected cwd or server workspace restrictions.
- History request window: default 8 KiB, range 4–16 KiB; applies to initial, older, and newer requests.
- Conversation-card initial preview: default 12 lines, range 4–40, with Show more/Show less controls. Chooser descriptions retain their two-line default.
- Cost-refresh cadence: every N accepted prompts, default 1, range 1–100. Opening a run always fetches current usage. At cadence thresholds, refresh once the new run is verified and again at completion, with up to four running-job usage attempts. Status polling is independent. Missing/late usage is marked pending, refresh failures retain the last known value, and a value carried from a previous run is explicitly labeled Last refreshed run cost. Figures are reported run usage, not an accumulated conversation total or account balance.
The Options gear is available in authenticated chooser/new/session views; Reset options restores defaults without deleting MRU history or counters.
## Data schema and API
There is **no database**. Expiring browser sessions, login attempts, and up to 100 active/recent jobs are in memory; restarting the service loses those records, not Warp runs. A job stores an opaque random ID, state, run ID, run-verification flag, conversation ID and separate conversation-trust flag, canonical launch cwd and requested cwd (original input while resolution is pending, canonical path otherwise), directory-resolution-pending flag, selected model, original prompt (at most 4096 characters), generic error, at most 16 KiB of progress output, and private process/cancellation bookkeeping. Public jobs contain `id`, `state`, `run_id` (null until that run is verified), `conversation_id` (null until trusted), `cwd`, `requested_cwd`, `directory_pending`, `model` (null for Default), `prompt`, `output`, `error`, `can_cancel`, and `can_resume`; process handles, PIDs, trust internals, and task/event objects are never exposed. A per-job mode-0600 task file in `~/.local/state/warpweb/jobs/<id>/task.txt` holds the prompt and any directory-recovery instructions while the CLI runs and is removed afterward. Warp persists conversations and usage.
The server uses only `GET /agent/runs` (cursor, sort, execution location), `GET /agent/runs/{runId}`, and `GET /agent/runs/{runId}/conversation` through server-only `WARP_API_KEY`. The installed CLI also supplies the read-only model catalog. Browser endpoints:
- `GET /api/session`, `POST /api/login`, `POST /api/logout`: password-gated browser session management.
- `GET /api/runs?scope=local|cloud|all&cursor=...&limit=...`: bounded chooser cards with usage and capabilities.
- `GET /api/runs/{runId}`: detail/capabilities plus conversation-availability probe. `GET /api/runs/{runId}/metadata`: the same card metadata without fetching history, for inexpensive status/usage refresh. These detail responses include nullable `local_job` for registry-associated local CLI jobs; cards include `can_send`, local-CLI `conversation_id`, and a validated `session_link`.
- `GET /api/runs/{runId}/history?size=8192&before=<turn-index>|after=<turn-index>`: bounded actor turns; returns start/end cursors and older/newer flags. Each turn contains actor, title, timestamp, body, tool/continued flags, block ID, zero-based fragment index, total fragment count, content kind (`text`, `action`, `action_result`), and optional supplied action ID. Block identity uses upstream message ID when available, otherwise traversal index; adjacent fragments of a block are rejoined in the browser. Invalid cursors return 409 and trigger a recent-history reload.
- `POST /api/render`: accepts `{text}` under authentication and Origin validation; returns sanitized `{html}` or null for plain-text fallback. Source is capped at 64 KiB UTF-8 (and 65536 characters at request validation), HTML at 256 KiB. Incomplete blocks and larger text stay plain; the browser caches up to 32 render results.
- `GET /api/models`: authenticated CLI catalog, returning `{models: [id, ...], available: bool}`. Discovery timeout is ten seconds, output capped at 128 KiB and 1000 entries, successful results cached for five minutes, and model IDs syntax-validated. Unavailable discovery returns an empty list with Default still supported. No credentials are returned or included in CLI arguments.
- `POST /api/jobs`: prompt plus optional cwd/model to start a local task. `GET /api/jobs`: authenticated running/stopping app-owned job snapshots for reload recovery. `GET /api/jobs/{jobId}`: job status, cancellation/resume capability, verified live run ID, requested/launch cwd, model, original prompt, and bounded progress. `POST /api/jobs/{jobId}/cancel`: authenticated, Origin-protected cancellation, returning 202 with a job snapshot; unknown jobs return 404 and unowned/already-exited processes return 409.
- `POST /api/jobs/{jobId}/messages`: authenticated, Origin-protected next-turn launch from a trusted terminal owned job, even when REST is unavailable or upstream status lags; returns 409 until cleanup/conversation verification permits continuation, 404 for unknown jobs. Optional cwd defaults to that job's requested/launch cwd. `POST /api/runs/{runId}/messages`: finished external local CLI continuation, or trusted safely exited app-owned continuation despite stale upstream status. All turn launches validate optional models against the installed catalog and preserve server concurrency/conversation locks.
`python3 -m tools.hash_password` prompts without argv and prints a random-salt PBKDF2-HMAC-SHA3-256 `WARP_API_HASH=...` verifier for private storage. Its `--env-file` option instead atomically updates a mode-0600 environment file without printing the verifier; other entries are preserved.
## Installation tooling
`INSTALL.md`, linked from the README, documents the Personal-token flow and local/public setup. `INSTALL.sh` runs the standard-library `tools/install.py` helper. `--check`/`--help` are non-destructive; interactive setup creates/reuses `.venv`, installs server requirements, collects a hidden token, invokes the non-printing password hasher, and writes mode-0600 credentials under `~/.config/warpweb/warpweb.env` plus a user systemd unit with absolute checkout-specific paths. No secrets are passed in argv or written into the unit. The config directory and private backups are mode 0700, with at most 25 backups per replaced file. Replacing an existing installation requires REPLACE confirmation; enabling/start/restart requires a separate confirmation. `--no-start` installs configuration/unit and daemon-reloads but does not restart.
Installer defaults are loopback-only HTTP at `127.0.0.1:8797`, exact allowed Origin, Secure cookies/HTTPS enforcement disabled for this local mode, and cwd roots restricted to the checkout. Explicit HTTPS origins enable Secure cookies and HTTPS enforcement; `WARPWEB_PUBLIC_URL` supplies the validated redirect origin. No personal hostname is embedded in the source; public deployments must explicitly configure `WARPWEB_ALLOWED_ORIGINS` and `WARPWEB_PUBLIC_URL` privately. Missing or invalid public-origin configuration returns 503 rather than redirecting to untrusted input. Existing public deployments must set the public URL before their next restart. TLS/DNS/proxy installation and lingering remain operator responsibilities. Generated units log to the user journal; the existing personal service's file logging remains unchanged until explicitly replaced.
`.gitignore` excludes credentials/environment files, runtime data/logs, backups, Python/native build output, caches, virtual environments, editor metadata, the current local screenshot captures, and the three personal installed deployment snapshots. Portable examples under `deploy/*.example` are tracked instead; personal files are not deleted or applied to the current service.
Generated units use unquoted path directives with escaped systemd specifiers; `/usr/bin/env` launches the quoted virtualenv executable so checkout paths containing spaces, dollar signs, percent signs, or quotes remain usable. Unsafe raw path endings/control characters are rejected before installation changes. Regression coverage runs the real systemd unit parser without installing or starting a unit.
## Business and security rules
The service fails closed without the password verifier or Warp API key, does not expose the key to the browser, and sets Secure/HttpOnly/SameSite cookies, no-store, HSTS, and a restrictive CSP. Browser sessions last twelve hours; five failed logins per IP block further attempts for fifteen minutes. Every mutating request requires a configured allowed Origin. Passwords and user prompts are never placed in CLI arguments.
The CLI gets a fixed instruction to read the private task file and uses `--no-snapshot`. Launch cwd is restricted to configured local roots (`/home/michael`, archive projects, `/tmp/warpweb`); this is not an OS sandbox and does not confine every command an agent can execute. Missing requested directories inside a root launch from the nearest existing allowed ancestor. Missing paths outside roots, including workspace-root name typos, are search hints only: launch from the first existing configured root rather than rejecting the typo. Private instructions retain the original text plus its interpreted path and tell the agent to search all existing configured roots, change directory if unambiguous, or ask for clarification and finish the turn; never create a directory or silently work in the fallback. Existing outside-root directories, files/non-directory ancestors inside a workspace, explicit outside-root `..` escapes, symlink escapes from a workspace, and malformed requests remain rejected; recovery requires an existing allowed launch base. Public `requested_cwd`/`directory_pending` distinguish unresolved requests from actual launch cwd; unresolved fallback cwd is not added to MRU as a resolved choice.
A maximum of two jobs run at once, with a fifteen-minute process timeout. Same-conversation running/stopping jobs are rejected. Preview and submission share capability checks: external `CLI / LOCAL` runs require a valid conversation UUID and state `SUCCEEDED`, `FAILED`, `ERROR`, or `CANCELLED`; app-owned safely exited jobs may override stale upstream active status only with trusted conversation identity and confirmed cleanup. Desktop/cloud/unknown external active states remain read-only. Model selectors apply to each new CLI execution through validated `--model`, never change a currently running model, and are retained with session drafts during navigation.
Live and completed run IDs are exposed only after REST confirms `source=CLI` and `execution_location=LOCAL`; live verification makes at most four attempts, with completion verification retaining its four-attempt retry. Cloud creation is never used. The installed CLI and researched public REST API/SDK expose no active-run messaging endpoint; desktop control is not emulated. Shared-session links must be HTTPS on `app.warp.dev` or `oz.warp.dev`, with no embedded credentials or nonstandard port. No session is automatically shared.
The public API supplies whole normalized conversations, not a server-side stream/history cursor; this backend paginates turns, splitting long bodies into small Unicode-safe parts. Tool inputs/results remain readable plain text. Prose uses `markdown-it-py` CommonMark/table rendering with raw HTML disabled and `nh3` tag/attribute sanitization; scriptable URL schemes, remote images, comments, and active markup are excluded. HTML is inserted only from the authenticated sanitizer endpoint, and CSP is unchanged. Partial-block rendering intentionally falls back to plain text until all adjacent fragments have loaded.
